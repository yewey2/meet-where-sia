# Security policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in a public GitHub issue, discussion, pull request, or shared plan.

Use GitHub's **Report a vulnerability** button on this repository's **Security** tab. If private vulnerability reporting is not available, contact the maintainer privately through the contact method shown on the GitHub profile for [`@yewey2`](https://github.com/yewey2).

Include:

- the affected route or feature;
- clear reproduction steps;
- the likely impact;
- any proof of concept with secrets and personal data removed; and
- whether you believe the issue is being actively exploited.

Please allow a reasonable period for investigation and remediation before public disclosure. Do not access other users' plans or data, degrade the service, or perform high-volume testing.

## Scope

Security reports are especially useful for authentication or authorisation bypasses, shared-plan data exposure, session handling, injection, secret leakage, and abuse of server-side integrations.

Incorrect meeting suggestions, stale third-party data, and availability problems are normally bugs rather than security vulnerabilities unless they cross a trust boundary or expose data.
